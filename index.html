Design principles

Guarantees provided by the language, not by exhaustive testing.

Termina was shaped by six principles that put correctness and analyzability first — so the cost of verification falls out of the design.

Reactive model

Systems are built from tasks, handlers and resources that communicate through ports and channels — the architecture is in the language.

Run-to-completion

Every reaction runs to completion without preemption, making the timing of each action predictable and composable.

Memory safety

Linear box types and explicit ownership rule out use-after-free, leaks and data races by construction.

Deterministic memory

No hidden allocation. Pools and fixed-capacity structures make memory usage bounded and known ahead of time.

Ease of use

A familiar imperative syntax with strong typing — approachable for embedded engineers coming from C or Ada.

Analyzable timing

The compiler extracts timing and data-flow models straight from the source, ready for schedulability analysis.

In code

Declare reactive entities, explicitly.

A task class states its ports, its private state and the actions triggered by incoming events. Everything the transpiler needs to reason about the architecture is right there in the declaration.

  • Ports, not globals. Tasks talk through typed ports — never shared references.
  • Declared architecture. Instances, priorities and connections live in one application module that the transpiler checks.
  • Bounded by construction. No recursion, no unbounded loops, predictable WCET.

The reactive model

Six building blocks, one analyzable system.

Every Termina program is composed from a small set of first-class entities. The transpiler knows how they connect — and uses it to reason about the whole system.

emitter

Event sources

Periodic, sporadic or interrupt-driven sources that start a transaction.

task class

Autonomous work

Run-to-completion units that react to events arriving on their ports.

handler class

Interrupt handling

Bounded responders bound to hardware events, with strict timing.

resource class

Shared state

Protected data accessed only through ports — no direct references, no races.

channel

Message passing

Typed queues that move messages between tasks with bounded capacity.

pool

Deterministic memory

Fixed-capacity allocators for box values — no hidden heap.
