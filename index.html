The Termina programming language

A domain-specific language for critical real-time embedded systems

Termina simplifies the implementation of real-time on-board software and reduces the cost of validating and verifying it. Its transpiler produces MISRA-compliant C, supported on RTEMS, FreeRTOS, and POSIX through a portable abstraction layer.

Why Termina

Verification drives the cost of critical software

In the standards that govern on-board and safety-related software, much of the budget goes into demonstrating properties that the implementation language never expressed: that loops terminate, that memory is bounded, that shared state is protected. Termina states those properties in the program itself, and the transpiler checks them on every build.

Reactive by structure

A program is a set of components that respond to events: timers, interrupts, messages. The structure a designer draws is the structure the code declares.

Run-to-completion semantics

Every action runs to completion. Loops carry a static bound and recursion is rejected, so worst-case execution times can be derived from the source.

Deterministic memory

There is no heap. Dynamic storage comes from fixed-capacity pools, as owned blocks that must be released or transferred exactly once. Leaks and use-after-free are compile-time errors.

Automatic protection

The transpiler analyzes how each shared resource is used and generates the synchronization it needs: a priority-ceiling mutex, interrupt masking, atomic operations, or none at all.

Readable MISRA C

The output is C meant to be read: explicit casts, designated initializers, bounds-checked array access. It compiles with the toolchains embedded projects already use.

Portable across targets

The same generated code runs on RTEMS 5 on a LEON3, on FreeRTOS 10 on an STM32, and on a POSIX host for development, through the Termina OSAL.

The language

Components declare their ports; the application connects them

A task class states the events it reacts to, the interfaces it uses, and the actions it executes. Instances and their connections are declared in a separate application module, so the transpiler sees the complete system and can verify it as a whole.

  • Typed ports. Components reach the rest of the system only through their ports. There are no globals to share by accident.
  • Explicit outcomes. Actions return a Status value, and variant types make failure handling part of the signature.
  • Inspectable output. Every class becomes plain C in the output tree, with names that match the source.

The reactive model

The vocabulary of a Termina system

Applications are assembled from a small set of constructs. The transpiler knows what each one is and how they are connected, and it verifies that knowledge on every build.

emitter

Event sources

Periodic timers, hardware interrupts, and system start-up. Every activity in the system begins at one of them.

task class

Scheduled components

Components with their own thread and a fixed priority. Each of their actions runs to completion.

handler class

Interrupt context

Components whose single action runs in the context of the interrupt that fires it, and delegates longer work to a task.

resource class

Protected state

Shared data reached only through interfaces, with mutual exclusion generated by the transpiler.

channel

Message queues

Bounded, typed queues that carry messages between components asynchronously.

pool

Block allocators

Fixed-capacity sources of owned box blocks, the only dynamic memory in the language.

Toolchain

One container, ready to build

The project distributes a Docker image with the transpiler, the OSAL, and the SPARC and Arm cross-toolchains, so a working environment is one pull away on any host. Editor support and documentation complete the set.

docker-termina ↗

The development image, published on GHCR. Pin an exact version tag, such as v0.4.0, to give a course or a project a reproducible setup.

VS Code extension ↗

Syntax highlighting and a language server for .fin files, published on the Marketplace as termina-lang.termina. Works inside the container through Dev Containers.
